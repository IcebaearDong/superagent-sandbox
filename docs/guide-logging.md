# Logging

harnessctl keeps the state directory, the resolved profile and the job queue in one place.
This page describes what to expect from a clean installation.

## Overview

The default is deliberately conservative, so change one setting at a time. This page is part of the harnessctl documentation set. When the cache is cold the first request takes noticeably longer. It is not neccessary to restart the service after a settings change.

After a change, restart the process so that the new value is read. Diagnostics go to standard error so that the normal output stays clean. A successful run prints nothing beyond the final line. The summary is usefull when you need to compare two runs.
