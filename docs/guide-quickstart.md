# Quick start

harnessctl keeps the state directory, the resolved profile and the job queue in one place.
This page describes what to expect from a clean installation.

## Overview

A successful run prints nothing beyond the final line. It is written for operators who already have the command installed. Use the verbose flag when you need to see why a step was skipped. The flag is availabe in every build after version four.

The tool never writes outside the directory named on the command line. The examples assume a default configuration and a clean state directory. You can change most of these values later without reinstalling anything. Backward compatability is kept for two release cycles.

Diagnostics go to standard error so that the normal output stays clean. After a change, restart the process so that the new value is read. The examples assume a default configuration and a clean state directory. It is not neccessary to restart the service after a settings change.

## Before you start

Both forms are accepted, so existing scripts do not need to be rewritten. When the cache is cold the first request takes noticeably longer. Diagnostics go to standard error so that the normal output stays clean. The summary is usefull when you need to compare two runs.
